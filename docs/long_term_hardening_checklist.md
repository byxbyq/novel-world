# 长线加固路线图（P3）

> 定位：不影响当前主程序运行的长线完善项。按安全 / 性能 / 运维 / 合规四域组织，
> 每项含【现状】【行动项】【验收标准】，可逐项领取执行。

---

## 一、安全层面

### 1.1 日志脱敏
- **现状**：日志会输出存档/配置的绝对路径（如 `H:\素材资源\...`），API Key 已在配置层隔离（`data/ai_config.json` 不再入 git），但日志未做统一过滤器。
- **行动项**：
  1. 在 `app.py` 增加 logging Filter，将路径中的用户目录替换为 `~`；
  2. 全局禁止 `logger.*` 直接输出含 `api_key`/`token` 字段的对象（提供 `mask_secret()` 工具函数）。
- **验收**：grep 全量日志输出，无绝对用户路径、无明文 Key。

### 1.2 依赖漏洞扫描 ✅（2026-08-10 完成）
- **现状**：已有 `requirements.lock` 精确锁版（2026-08-10 基线）；CI 已增加 `audit` job 跑 `pip-audit -r requirements.lock`，发现高危 CVE 会阻断合并。
- **行动项**：
  1. CI 增加 `pip-audit`（或 `safety check -r requirements.lock`）步骤；
  2. 每月人工复核一次 CVE 通告，重点：flask / openai / cryptography / urllib3。
- **验收**：CI 中出现依赖扫描 job，高危漏洞阻断合并。

### 1.3 路径遍历防护
- **现状**：存档槽位名（slot）直接拼文件路径（`storage.py`），前端传入 `../../etc/passwd` 这类值理论上可越权读写。当前仅本机使用，风险低；一旦对外暴露必须处理。
- **行动项**：
  1. `backend/storage.py` 增加 `_safe_slot(slot)` 校验：仅允许 `[a-zA-Z0-9_\-\u4e00-\u9fa5]`，且解析后路径必须仍在 `SAVES_DIR` 内（`os.path.commonpath` 校验）；
  2. `api/save_api.py` 各端点入口统一调用该校验。
- **验收**：新增测试：`slot="../evil"` 返回 400 且不产生文件。

## 二、性能层面

### 2.1 内存泄漏排查 ⚠️（环形上限已完成，压测未做）
- **现状**：`_collision_history` 已加环形上限 500 条（`_COLLISION_HISTORY_MAX`，含单测）；`char.memory` 已有 30 条上限；`_preview_text` 每章 reset。tracemalloc 50 章压测需真实 AI 调用，待排期。
- **行动项**：
  1. 用 `tracemalloc` 跑 50 章 DM 推演，对比前后 top10 内存占用；
  2. 给 `_collision_history` / `char.memory` 增加环形上限（如各保留最近 500 条）。
- **验收**：连续 50 章推演内存增长 < 100MB 且趋于平稳。

### 2.2 多线程存档读写冲突
- **现状**：章节生成走 `_engine_lock`，存储已改为原子写入（.tmp + os.replace），单文件损坏概率极低；但并发保存（自动保存 + 手动保存同时）仍可能互相覆盖。
- **行动项**：在 `Storage` 内加 `threading.Lock` 串行化 save/load。
- **验收**：10 线程并发 save 不产生损坏文件（可用压测脚本验证）。

### 2.3 磁盘写入损耗 ⚠️（gzip 已完成，分片存储未做）
- **现状**：新存档已改为 gzip 压缩写入（重复文本压缩率 >50%），读取时按魔数自动识别旧明文存档，无感兼容。按章分片存储需改存档格式 + 迁移逻辑，待排期。
- **行动项**：
  1. 章节正文按章分片存储（`saves/chapters/{n}.json`），主存档只存状态；
  2. 或保存时压缩（`gzip`）全文字段。
- **验收**：100 章存档单次保存耗时 < 500ms。

## 三、运维层面

### 3.1 AI 调用量统计与超额预警
- **现状**：已有 `data/ai_usage.json` 与 `/api/ai/usage`，前端模型弹窗可查看；无超额预警。
- **行动项**：
  1. `data/ai_config.json` 增加 `monthly_quota`（token 或请求数上限）；
  2. 用量达 80% 时前端顶部横幅提醒，达 100% 时生成类接口返回 429（可配置强制/仅提醒）。
- **验收**：配置低额度后触发预警横幅。

### 3.2 打包发布与版本回滚
- **现状**：有 `build_exe.spec`（PyInstaller），版本号未系统管理；回滚依赖 git。
- **行动项**：
  1. `app.py` 注入 `APP_VERSION`（从 git tag 或 VERSION 文件读取），`/api/health` 返回版本号；
  2. 发布流程文档化：打 tag → 构建 exe → 存档兼容性检查（旧存档加载测试）；
  3. 回滚即 `git checkout <tag>` 重新构建，存档格式变更必须写迁移逻辑。
- **验收**：`/api/health` 含 version 字段；发布记录文档存在。

## 四、合规层面

### 4.1 开源协议核查 ✅（2026-08-10 完成）
- **现状**：全部依赖为宽松协议（MIT/Apache/BSD/MPL/ZPL），无 GPL 传染风险；许可清单已生成至根目录 `THIRD_PARTY_LICENSES.md`（pip-licenses 基于 requirements.lock 基线）。
  | 依赖 | 协议 |
  |---|---|
  | Flask / Werkzeug / Jinja2 | BSD |
  | openai / httpx | Apache-2.0 / BSD |
  | numpy | BSD |
  | PyYAML | MIT |
  | cryptography | Apache/BSD 双协议 |
  | waitress | ZPL/MIT |
- **行动项**：发布商用版本时，随包附 `THIRD_PARTY_LICENSES` 文件（`pip-licenses` 自动生成）。
- **验收**：发布包内含第三方许可清单。

### 4.2 素材与字体版权
- **现状**：前端样式为纯 CSS 渐变，未引入外部图片/字体素材，无版权风险；`修仙大世界.txt` 为自有设定文本。
- **行动项**：后续若引入图标库/字体/背景图，只允许使用：思源系列（OFL）、阿里巴巴普惠体（免费商用）、Iconify（按图标单独核协议）；禁止直接使用来源不明的网文素材。
- **验收**：素材目录附带来源与协议说明（`assets/LICENSES.md`）。

### 4.3 AI 生成内容合规
- **现状**：已有去AI味后处理与质量审计，但无内容安全过滤。
- **行动项**：对外发布前，在正文落库前增加敏感词/合规过滤钩子（`chapter_fixer` 管线末端），并保留 provider 侧内容审核依赖说明。
- **验收**：过滤钩子存在且可配置开关。
